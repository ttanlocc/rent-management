  <action>
Create three API route files following the exact patterns from app/api/payments/route.ts and app/api/payments/[id]/route.ts.

**app/api/leases/route.ts:**

GET /api/leases (list with filtering):
- Auth check using createServer() pattern
- Parse query params: tenant_id, room_id, status, page, limit
- Validate with leaseQuerySchema
- Query leases from Supabase with select including relations:
  ```
  *, tenant:tenants(id, full_name, room:rooms(name)), room:rooms(id, name, base_rent)
  ```
- Apply filters: .eq('tenant_id', tenant_id), .eq('room_id', room_id), .eq('status', status)
- Pagination with .range(from, to) and .order('created_at', { ascending: false })
- Return { leases, pagination } using createSuccessResponse
- RLS handles data isolation

POST /api/leases (create with schedule generation):
- Auth check
- Parse JSON body with createLeaseSchema
- Verify tenant ownership: query tenant -> room -> property -> user_id === user.id
- Verify room ownership: query room -> property -> user_id === user.id
- Check no active lease exists for this tenant+room combo:
  ```sql
  .from('leases').select('id').eq('tenant_id', tenant_id).eq('room_id', room_id).eq('status', 'active')
  ```
  If found, return errors.conflict('Nguoi thue nay da co hop dong dang hoat dong cho phong nay')
- Insert lease record with status 'active'
- After successful insert, generate payment schedule:
  - Calculate months between start_date and end_date
  - For each month, insert into lease_payment_schedules:
    - lease_id: new lease id
    - due_date: start_date day-of-month for each month (use JS date arithmetic)
    - expected_amount: monthly_rent
    - status: 'pending'
  - Use Supabase .insert() with array of schedule rows for batch insert
- Return 201 with created lease including schedules

**app/api/leases/[id]/route.ts:**

GET /api/leases/[id] (detail with schedules):
- Auth check
- Query lease with full relations:
  ```
  *, tenant:tenants(id, full_name, phone, room:rooms(name)), room:rooms(id, name, base_rent), schedules:lease_payment_schedules(*, payment:payments(id, amount, payment_date, payment_status))
  ```
- Order schedules by due_date ascending
- Ownership verification via relation chain
- Return lease with all details

PUT /api/leases/[id] (update and regenerate schedule):
- Auth check
- Parse body with updateLeaseSchema
- Verify ownership
- Update lease record
- If start_date, end_date, or monthly_rent changed:
  - Delete only 'pending' schedule entries (preserve 'paid' and 'partial' entries)
  - Regenerate pending schedule entries using updated terms
  - Use the same month-by-month generation logic as POST
- Return updated lease

DELETE /api/leases/[id]:
- Auth check
- Verify ownership
- Delete lease (CASCADE will delete schedules)
- Return { deleted: true }

**app/api/leases/[id]/terminate/route.ts:**

POST /api/leases/[id]/terminate (early termination - LEASE-07):
- Auth check
- Parse body: { termination_date: string (ISO date), notes?: string }
- Verify ownership
- Validate termination_date is between lease start_date and end_date
- Update lease: status = 'terminated', end_date = termination_date, notes = termination notes
- Delete pending schedule entries with due_date > termination_date
- Update tenant: move_out_date = termination_date, is_active = false
- Update room: status = 'vacant'
- Return updated lease

All routes follow error handling pattern: try/catch with ZodError check, handleSupabaseError, console.error, errors.internal().
