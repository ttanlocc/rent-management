  <action>
Create a SQL migration file following the pattern from 20260215000001_create_payments.sql.

**leases table:**
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- tenant_id: UUID REFERENCES tenants(id) ON DELETE CASCADE NOT NULL
- room_id: UUID REFERENCES rooms(id) ON DELETE CASCADE NOT NULL
- start_date: DATE NOT NULL
- end_date: DATE NOT NULL
- monthly_rent: DECIMAL(15,2) NOT NULL CHECK (monthly_rent > 0)
- deposit: DECIMAL(15,2) NOT NULL DEFAULT 0 CHECK (deposit >= 0)
- status: VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'expiring_soon', 'expired', 'terminated'))
- notes: TEXT
- created_at: TIMESTAMPTZ DEFAULT NOW()
- updated_at: TIMESTAMPTZ DEFAULT NOW()
- Add CHECK constraint: end_date > start_date

**lease_payment_schedules table:**
- id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- lease_id: UUID REFERENCES leases(id) ON DELETE CASCADE NOT NULL
- due_date: DATE NOT NULL
- expected_amount: DECIMAL(15,2) NOT NULL CHECK (expected_amount > 0)
- status: VARCHAR(20) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'paid', 'overdue', 'partial'))
- payment_id: UUID REFERENCES payments(id) ON DELETE SET NULL (optional link to actual payment record)
- notes: TEXT
- created_at: TIMESTAMPTZ DEFAULT NOW()
- updated_at: TIMESTAMPTZ DEFAULT NOW()
- Add UNIQUE constraint on (lease_id, due_date) to prevent duplicate schedule entries

**RLS policies:**
- Enable RLS on both tables
- leases: FOR ALL USING tenant_id IN (SELECT t.id FROM tenants t JOIN rooms r ON t.room_id = r.id JOIN properties p ON r.property_id = p.id WHERE p.user_id = auth.uid())
- lease_payment_schedules: FOR ALL USING lease_id IN (SELECT l.id FROM leases l JOIN tenants t ON l.tenant_id = t.id JOIN rooms r ON t.room_id = r.id JOIN properties p ON r.property_id = p.id WHERE p.user_id = auth.uid())

**Indexes:**
- idx_leases_tenant_id ON leases(tenant_id)
- idx_leases_room_id ON leases(room_id)
- idx_leases_status ON leases(status)
- idx_leases_dates ON leases(start_date, end_date)
- idx_lease_schedules_lease_id ON lease_payment_schedules(lease_id)
- idx_lease_schedules_due_date ON lease_payment_schedules(due_date)
- idx_lease_schedules_status ON lease_payment_schedules(status)

**Triggers:**
- Reuse update_updated_at_column() function for both tables (already exists from payments migration)
- CREATE TRIGGER update_leases_updated_at BEFORE UPDATE ON leases FOR EACH ROW EXECUTE FUNCTION update_updated_at_column()
- CREATE TRIGGER update_lease_schedules_updated_at BEFORE UPDATE ON lease_payment_schedules FOR EACH ROW EXECUTE FUNCTION update_updated_at_column()

**SQL function for schedule generation:**
Create a PostgreSQL function `generate_lease_payment_schedule(p_lease_id UUID)` that:
1. Deletes existing schedule entries for the lease (WHERE status = 'pending' — preserve paid/partial entries)
2. Reads the lease's start_date, end_date, monthly_rent
3. Generates one row per month from start_date to end_date (using generate_series with '1 month' interval)
4. Each row: due_date = first day of each month (or start_date day-of-month), expected_amount = monthly_rent, status = 'pending'
5. Returns the number of rows inserted

Use Vietnamese comments for clarity matching existing migration style.
